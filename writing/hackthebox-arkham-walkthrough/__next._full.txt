21:T41c3,<h2 id="machine-overview">Machine Overview</h2><p>Name: Arkham<br>OS: Windows Server 2019<br>Difficulty: Medium<br>IP: 10.129.228.116</p><h2 id="attack-chain-at-a-glance">Attack Chain at a Glance:</h2><p>Anonymous SMB -&gt; LUKS-encrypted disk image -&gt; crack password (batmanforever) -&gt; extract JSF HMAC/encryption key (JsF9876-) -&gt; forge malicious ViewState -&gt; Java deserialization RCE -&gt; shell as Alfred -&gt; backup.zip -&gt; OST email -&gt; Batman's password -&gt; WinRM lateral move -&gt; mount C$ over SMB -&gt; read root.txt</p><h2 id="the-mindset-before-the-shell">The Mindset Before the Shell</h2><p>The attack path depends on a few concrete checks:</p><p>1. Follow the data, not the script. Every step should answer a question. Each finding is a breadcrumb, not a destination.<br>2. Theme awareness matters. BatShare, Alfred, Bruce, batmanforever - these hints are deliberate. Theme-based wordlists and educated guesses save time.<br>3. Understand the exploit. This box teaches LUKS, JSF serialization, HMAC signing, and Windows UAC. Knowing why something works lets you adapt when it breaks.<br>4. Privilege is layered. Anonymous -&gt; low user -&gt; mid user -&gt; admin. Focus on the current link in the chain.</p><h2 id="phase-1-reconnaissance-mapping-the-surface">Phase 1: Reconnaissance: Mapping the Surface</h2><p>Every engagement starts with the same question: what can I reach?</p><p>Nmap -sC -sV -p- 10.129.228.116</p><p>This gives us a fast, complete picture of open services:</p><p>PORT STATE SERVICE VERSION<br>80/tcp open http Microsoft IIS 10.0<br>135/tcp open msrpc<br>139/tcp open netbios-ssn<br>445/tcp open microsoft-ds<br>8080/tcp open http Apache Tomcat 8.5.37<br>49666/tcp open msrpc<br>49667/tcp open msrpc</p><p>What stands out?</p><p>- Port 80 is Default IIS. Probably not the initial vector.<br>- Port 8080 is Apache Tomcat 8.5.37. Java app servers love deserialization issues.<br>- Ports 139/445 are SMB. Anonymous access is a common quick win.<br>- RPC ports confirm it is Windows; less immediately useful.</p><p>Decision: check SMB first, then dig into Tomcat.</p><figure><img src="/writing/media/b85896e8de22948ce6b05634.webp" alt="HackTheBox “Arkham” Walkthrough, figure 2" width="1200" height="931" loading="lazy" decoding="async"></figure><h2 id="phase-2-smb-enumeration-the-door-swings-open">Phase 2: SMB Enumeration: The Door Swings Open</h2><p>SMB null sessions are still one of the most reliable common checks in CTFs and real environments.</p><p>Smbclient -N -L //10.129.228.116</p><p>Output:</p><p>Sharename Type Comment<br> - - - - - - - - - - -<br>ADMIN$ Disk Remote Admin<br>BatShare Disk Master Wayne's secrets<br>C$ Disk Default share<br>IPC$ IPC Remote IPC<br>Users Disk</p><p>A custom share named BatShare with the comment "Master Wayne's secrets"? That is where we go next.</p><p>Smbclient -N //10.129.228.116/BatShare</p><p>Inside, we find a single archive:</p><p>Smb: \&gt; ls<br>&nbsp;appserver.zip A 4046695</p><p>Smb: \&gt; get appserver.zip</p><p>Extracting it reveals two files: IMPORTANT.txt (a note from Bruce to Alfred about a Linux backup) and backup.img.</p><p>File backup.img<br># backup.img: LUKS encrypted file, ver 1 [aes, xts-plain64, sha256]</p><figure><img src="/writing/media/2332d58bfa64c86a198a2940.webp" alt="HackTheBox “Arkham” Walkthrough, figure 3" width="1200" height="427" loading="lazy" decoding="async"></figure><h2 id="phase-3-cracking-the-luks-image">Phase 3: Cracking the LUKS Image</h2><p>LUKS is designed to be slow. Brute-forcing the entire rockyou.txt list at roughly 16 attempts per second would take days. We need a smarter approach.</p><p>This is where theme awareness pays off. The share is BatShare. With it, we can forge arbitrary ViewStates.</p><figure><img src="/writing/media/55bc960001b14e4db9954343.webp" alt="HackTheBox “Arkham” Walkthrough, figure 6" width="598" height="120" loading="lazy" decoding="async"></figure><h2 id="phase-4-jsf-viewstate-deserialization-rce">Phase 4: JSF ViewState Deserialization RCE</h2><p>What is JSF ViewState?</p><p>JavaServer Faces (JSF) stores page state in a serialized base64 blob called the ViewState. When the user submits a form, the server deserializes that blob to reconstruct the page.</p><p>Java deserialization of untrusted data is a well-known path to Remote Code Execution. Normally, the ViewState is protected by encryption and HMAC signing - so clients cannot tamper with it. But we just extracted the key.</p><p>The ViewState Crypto Structure</p><p>Base64( DES_ECB_encrypt(payload) + HMAC_SHA1(encrypted_payload) )</p><p>- Encryption: DES-ECB with key JsF9876-<br>- MAC: HmacSHA1 with key JsF9876-<br>- MAC appended as the last 20 bytes</p><p>Building the Exploit</p><p>We use ysoserial to generate a malicious serialized Java object. The gadget chain CommonsCollections5 works with Apache Commons Collections 3.x, which Tomcat 8.5.37 ships with.</p><p>Environment setup:</p><pre tabindex="0" aria-label="text code or terminal block 1"><code data-language="text">wget https://github.com/frohoff/ysoserial/releases/latest/download/ysoserial-all.jar \ -O /opt/ysoserial.jarpip install pycryptodome - break-system-packagesysoserial needs Java 8-11. Anonymous SMB access is still a critical foothold. One misconfigured share handed us a full server backup.<br>2. Backups are dangerous.
